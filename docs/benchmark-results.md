# Benchmark results

Generated 2026-10-26T18:09:24.889570+00:00 with Python 3.12.10. 20 seeds x 9 scenarios x 3 systems = 540 runs. Rates are shown as `k/n = rate [Wilson 95% interval]`.

## Read this first

- **The scenarios were written by the same author as the system.** The rule-based hypotheses were built knowing these fault shapes, so strong results on them show the pipeline works end to end, not that it generalizes to unseen incidents.
- **Seeds vary only noise** (counts, jitter, timing), not the fault design. The intervals therefore understate the uncertainty about real incidents.
- **Recovery is simulated.** After an action, telemetry is generated by a simple world model: a fault stops only when the action that fixes it is the one executed. SentinelOps verifies this with its real SLO evaluator; the baselines have no verification step and treat an executed action as success.
- **The alert correlator is deliberately naive** (threshold alerts plus "blame the latest change"). A production correlator would be stronger, so the gap to it is an upper bound on the benefit, not a measured industry comparison.
- **Thresholds and weights were set by hand and not tuned on held-out data.**
- **Scenarios P1 and P2 are probes** written to exercise the falsification mechanism (a plausible leader that a direct test can disprove). They are reported separately and must not be read as a representative sample.

**Not run:** LLM only (ANTHROPIC_API_KEY is not set).

## Known gaps

- **S10 (two faults):** no system reports a multi-cause incident; the `complete_diagnosis_rate` row shows this. Naming one of the two causes counts as a correct top-1 but an incomplete diagnosis.
- **Not modelled:** S02, S04, S06, S07 (no database/cache/CPU signals in the demo shop), S11 (clock skew); S12 (unsafe action) is covered by policy tests, not here.
- **LLM-only baseline** runs only when `ANTHROPIC_API_KEY` is set; without it the comparison to an LLM is absent, not assumed.
